# Language Card 数据格式：V3（当前实现）

> **状态**：已实现。需求与验收清单见 `schema/v3-requirements.md`，V2 兼容基线见 `schema/v2.md`。
> **事实源**：`src/card-types.js`（marker/类型）、`src/card-model.js`（note 解析/序列化）、`src/spaces.js` / `src/space-manager.js`（发现与管理）、`src/editor.js` / `src/card-render.js`（UI）。
> **验证**：`npm run test:v3`（marker、payload、说明区、迁移向量）+ `npm test`（含 21 个 V2 兼容向量与 mock DOM 冒烟测试）。

## 1. 实现时采用的默认决策

| 需求文档的待确认项 | 采用的选择 |
| --- | --- |
| V3 识别键 | 沿用 `_t: "lc"`，写入 `v: 3`；V3 读取器**按 `v` 分派**，V2 卡片仍走旧解析路径 |
| 说明区开关语义 | 显示/隐藏开关（`_x`）；模式由类型定义 `explanationMode` 决定 |
| 别名语义 | `sectionAliases` 是「旧 note 键 → 新 note 键」的映射，同时用于渲染兜底与迁移 |
| 写 Space 描述 | `PATCH /api/spaces/{id}?updateMask=description`（双代回退）；401/403 时降级为复制 marker 手动粘贴 |
| 混合 feed 找类型 | 启动时按各类型 Space 拉 memo 列表，建立 `memoName → spaceName` 缓存；失败回退当前 URL Space |
| 重复头部 | 保留 modal header 为唯一头部，feed 卡片不再渲染 `🔤 Card` 文案，只留编辑按钮 |
| In use / Editing 高亮 | In use = 当前 URL Space 的类型（新建卡片目标），绿色高亮；Editing = 定义面板正在编辑的类型，蓝色高亮，两者独立 |
| 声明新类型 | 从空 `sections` 开始，不继承 JA/EN/ZH，由用户自行添加分区 |
| 编辑器预览 | 只保留 note raw content 的 `Memos Payload Preview`；marker 预览/复制按钮在管理面板内 |

## 2. 载体：两个位置，职责分离

| 位置 | 内容 |
| --- | --- |
| `space.description` | **卡片类型定义**（marker JSON，可夹在人类文字中） |
| `memo.content` | **卡片数据**（分区值 + 说明 + 版本标识 + 尾部 tags），不含任何定义字段 |

marker 提取沿用 V2 的「第一个 `{` 到最后一个 `}`」策略，但 V3 要求 `JSON.parse` 严格成功（不继承 V2 的坏 JSON 正则兜底）。

## 3. Space marker（卡片类型定义）

```json
{
  "_t": "lc", "v": 3,
  "typeId": "new-speak", "name": "New Speak", "order": 20,
  "explanationMode": "global",
  "sections": [
    { "key": "en", "label": "English", "color": "#38bdf8" },
    { "key": "newSpeak", "label": "New Speak", "color": "#34d399" }
  ],
  "sectionAliases": { "personal": "in room" }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_t` | `"lc"` | 固定标识，其它值忽略该 Space |
| `v` | `3` | V3 marker；`2`（V2 短 marker）会被当成**默认类型** |
| `typeId` | string | 类型 id；缺省时用 Space 资源名 |
| `name` | string | 显示名；缺省时用 Space 标题 |
| `order` | number | 全局类型排序，越小越靠前 |
| `explanationMode` | `"per-section"` \| `"global"` | 说明区模式，缺省 `per-section` |
| `sections` | array | **有序**分区定义；数组顺序 = UI 左到右顺序 = JSON 键序 |
| `sections[].key` | string | note content 里的键，允许任意自定义标签（如 `newSpeak`、`in room`） |
| `sections[].label/color` | string | label 用于显示；开关上的短 code 由 label 自动派生（`New Speak` → `NS`），不写入定义 |
| `sections[].defaultHidden` | boolean | 仅 `true` 时写入；新建卡片时该分区默认收起，编辑已有卡片时仍显示该卡片实际持有的分区。内置三分区模板（V2 marker 空间用）的 JA 在 `src/config.js` 里以同一字段声明为默认隐藏——模板不硬编码 key |
| `sectionAliases` | object | 旧键 → 新键；渲染时按别名兜底，迁移时按键名映射。**只由迁移向导逐键选择后写入**，管理面板不提供手工编辑 |

- 一个 Space 最多一个 marker；**多个 Space 各自带 marker 是正常状态**（V2 的「只允许一个」规则已废弃）。
- V2 marker（`v:2`）或缺失 `sections` 时回退到内置三分区（JA/EN/ZH）；V3 marker 显式 `sections: []` 表示「尚未定义分区」，不回退，用户在管理面板添加。
- 示例解读：「New Speak」类型只有 English 与 New Speak 两个分区；SKlang 中 `personal → in room`、而 `in house` 已被 `Proprietary` 占用，说明分区名是类型内自定义标签，必须显式声明映射，不能靠全局字典推断。
- 写回 description 时保留 marker 前后的人类文字，只替换 JSON 本身。

## 4. Note content（卡片数据）

```
content := json-object [ "\n" tag-tail ]
json-object := {"_t":"lc","v":3, <section key>: "value", ..., "_e": ..., "_x": false?}
```

```json
{"_t":"lc","v":3,"en":"cat","newSpeak":"nyaa","_e":{"en":"an animal","newSpeak":"a greeting"},"_x":true}
#vocab #daily
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_t` | `"lc"` | 必需 |
| `v` | `3` | 必需；V3 读取器据此分派 |
| `<section key>` | string | 分区值，键名来自类型 `sections[].key`；空值不写入 |
| `_e` | object \| string | 说明区内容：`per-section` 用 `{key: text}`，`global` 用单个字符串；空值不写入 |
| `_x` | boolean | 仅 `false` 时写入，表示本卡片隐藏说明区（默认显示，省略以缩短 note） |
| tail tags | `#tag #tag` | JSON 之后，`/#[^\s#]+/g` 提取，与 V2 相同 |

**禁止出现在 note 中**：`sections`、`order`、`label`、`code`、`color`、`explanationMode`、`typeId`、`sectionAliases`。
分区值至少一项非空才允许保存；tags 不算。编辑 V2 卡片时继续写回 V2 格式（不悄悄升级）。

## 5. 说明区（R3）

| 模式 | `_e` 形态 | 渲染位置 |
| --- | --- | --- |
| `per-section` | `{ "en": "...", "zh": "..." }` | 每个语言分区下方各自一块，位于分区 grid 之后 |
| `global` | `"shared text"` | 整张卡片的分区 grid 下方一块 |

编辑器里说明区在分区 grid 下方，其**显示开关**（`#lc-explanation-toggle`）位于说明区正上方、与 modal header 的分区 chips 完全分离；开关只影响 `_x`，不删除已输入的说明值。

## 6. 兼容与迁移

| 输入 | 处理方式 |
| --- | --- |
| V3 note (`v:3`) | 按所属 Space 类型渲染；未知键也显示（以键名作标签），不会静默截断 |
| V2 note (`v:2` / 无 `_t`) | 走 `parseCardMemo` 原路径，用内置三分区渲染；编辑时保持 V2 格式 |
| V2 marker (`{"_t":"lc","v":2}`) | 视为默认类型，仍可被发现、排序、编辑 |
| 无 marker 的 Space | 管理面板列出，可声明为类型 |
| 键名不匹配当前类型 | 管理面板扫描提示，用户确认后按键名映射迁移 |

迁移函数 `migratedContent()`：**只重命名 section 键**（同步映射 `_e` 内的键），保留 `_t`、未知键与 tail tags，并把 `v` 升到 `3`；不改 language/explanation 的框架。

迁移流程（**独立窗口**，不是内嵌表单）：管理面板里只有「Open migration wizard…」入口 → 扫描该 Space 的 memo → 逐条列出 note 与它真实的键值 → 每个不匹配的键由用户从当前类型的分区中选择目标（或「keep as-is」）→ 预览 before/after → 确认后逐条 PATCH。可选把本次选择保存为类型别名。失败逐条报告，不静默丢弃数据。

**读取器兼容优先**：历史 memo 不会被批量改写，V2 与无 header 卡片必须始终可读。

## 7. 客户端状态与 API

| localStorage 键 | 值 |
| --- | --- |
| `memos_lc_target_space_v2` | `{name, title}`，当前用于新建卡片的 Space（沿用旧键） |
| `memos_lc_enabled_langs_v2` | 只读兼容：V2 无内容卡片的回退组合；V3 不再提供 UI |

DOM 运行时标记：`data-lc-raw` / `data-lc-parsed` / `data-lc-force` / `data-lc-memo-name` / `data-lc-quick-actions` / `data-lc-slot` / `data-lc-explanation` / `<style id="lc-injected-style">`。

V3 新增的 API 调用（均双代回退：`/api/...` → `/api/v1/...`）：

- `GET /api/spaces` — 发现所有 Space 与 marker
- `GET /api/memos?parent=<space>` — 建立 `memoName → spaceName` 缓存；扫描不兼容 note
- `PATCH /api/spaces/{id}?updateMask=description` — 写 marker（**仅 Space 管理员**）
- `PATCH /api/memos/{id}?updateMask=content` — 保存/迁移 note

## 8. 与 V2 的差异速查

| 主题 | V2 | V3 |
| --- | --- | --- |
| 分区定义 | 全局 `CONFIG.languages` + 硬编码白名单 | Space marker `sections`，动态 |
| Space | 只允许一个目标 Space | 多个 Space = 多种卡片类型 |
| note 版本 | `v:2`，`_t` 决定是否渲染 | `v:3`，按版本分派；V2 仍可读 |
| 类型信息 | 无 | `typeId/name/order/explanationMode/sectionAliases` 只在 Space |
| 说明区 | 无 | 两模式 + 独立开关 + `_e`/`_x` |
| 首页开关 | 全局语言 pills | 已移除 |
| 卡片头 | `🔤 Card` + 编辑按钮 | 仅编辑按钮 |
| 快捷按钮 | Pin / Edit / Archive | + Copy Content |

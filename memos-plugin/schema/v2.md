# Language Card 数据格式：V2

> **状态**：V2 是**历史写入格式**；当前写入版本为 V3（见 `schema/v3.md`）。本文记录 V2 的实际行为，是读取器必须长期兼容的基线；21 个契约向量见 `tools/schema-v2.test.mjs`。
> **事实源**：`src/card-model.js`（读取）、`src/editor.js`（写入）、`src/spaces.js`（Space 标记）、`src/config.js`（常量）。
> 本文记录的是**代码实际行为**，不是理想设计；标注「怪癖」的条目是历史行为，V3 必须决定继承还是显式迁移。
> **可执行验证**：`npm run test:schema`（21 个向量直接调用真实解析器，见 `tools/schema-v2.test.mjs`）。

---

## 1. 载体与整体语法

一张 language card = 一条 Memos memo。格式存在 `memo.content` 里，而 `content` 是**纯文本**，不是结构化字段：

```
content := [前置文字] json-object [换行 tag-tail | 后置文字]
json-object := rawText 中「第一个 {」到「最后一个 }」的子串（含两端）
tag-tail := json-object 之后文本里所有 /#[^\s#]+/ 匹配项
```

编辑器实际输出（JSON 与 tags 之间恰好一个 `\n`，键序固定）：

```json
{"_t":"lc","v":2,"ja":"セレンディピティ","en":"serendipity","zh":"意外发现珍宝的运气"}
#vocab #daily
```

只写两种语言中任意组合也合法，例如 `{"_t":"lc","v":2,"en":"motor","zh":"电机"}`。
JSON 前后的任意人类可读文字都会被读取器容忍（但仍要求第一个 `{` 与最后一个 `}` 能框住一个可解析对象）。

## 2. JSON 对象字段

| 字段 | 写入类型 | 必需 | 语义 |
| --- | --- | --- | --- |
| `_t` | string，字面量 `"lc"` | 是 | 类型标识符，防误判。读取端严格比较，`_t` 为其它**真值**一律拒绝整张卡片 |
| `v` | number `2` | 是 | 格式版本。**读取端不按它分派**（见 §3、§8.1） |
| `ja` | string | 至少一项非空 | 日本語 section |
| `en` | string | 同上 | English section |
| `zh` | string | 同上 | 中文 section |
| `jp` / `cn` | string | 可选 | V1 遗留键，读取时 fallback 为 `ja` / `zh`；同名新键优先 |
| 其它键 | any | 可选 | 读取端不拒绝，但渲染与编辑都忽略（见 §8.8） |

**键序 = UI 顺序**：`_t`, `v`，然后按 `CONFIG.languages` 顺序（当前 JA → EN → ZH）追加非空语言值。
`JSON.stringify` 的对象插入顺序即最终顺序，`cardPresentLangs()` 也按同一顺序决定卡片列的排列。

**空语言值不写入**：编辑器对每个输入 `trim()`，空字符串跳过；保存要求至少一个语言槽非空（`tags` 不算）。

**语言值类型**：规范是 string；读取端对任意值做 `String(val).trim()`，所以 `{"en":123}` 会渲染成 `123`。

写入端规范的形式化描述（JSON Schema，仅覆盖 JSON 对象，不含 tail tags，也不是读取端校验器）：

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "Language Card V2 object (write-side norm)",
  "type": "object",
  "required": ["_t", "v"],
  "properties": {
    "_t": { "const": "lc" },
    "v": { "const": 2 },
    "ja": { "type": "string" }, "jp": { "type": "string" },
    "en": { "type": "string" },
    "zh": { "type": "string" }, "cn": { "type": "string" }
  },
  "additionalProperties": true,
  "anyOf": [
    { "required": ["ja"] }, { "required": ["jp"] }, { "required": ["en"] },
    { "required": ["zh"] }, { "required": ["cn"] }
  ]
}
```

> 根 README 的早期笔记里出现过 `"v": "2"`（字符串）。当前**写入端**只产生 number `2`；
> 读取端对字符串 `"2"`、乃至 `v:3` 都接受，因为没有任何 `v` 值校验（见测试向量）。

## 3. 识别规则（读取端）

`parseCardMemo(rawText, currentSpace)` 的实际判定顺序：

1. 没有 `{` → 拒绝。
2. `jsonCandidate` = 第一个 `{` 到最后一个 `}`；`tagsCandidate` = 最后一个 `}` 之后的全部文本。
3. `JSON.parse(jsonCandidate)`；失败则走**正则兜底**（见 §4）。
4. 结果不是 object → 拒绝。
5. `cardData._t` 存在且 !== `"lc"` → 拒绝。
6. 三条命中任一即可：
   - `isExplicitCard`：`cardData._t === "lc"`
   - `isLegacyCard`：`cardData.v` 为真值（含数字 `0`）**且**对象含 `en/ja/jp/zh/cn` 中至少一个键
   - `isDedicatedSpace`：`CONFIG.dedicatedSpaceKeyword` 非 null 且 `currentSpace` 包含它（**当前为 `null`，此路禁用**）
7. `tags` = `tagsCandidate.match(/#[^\s#]+/g)`。
8. `hasValues` = `en/ja/jp/zh/cn` 中至少一个值 truthy 且 `trim()` 后非空。
9. `!hasValues && tags.length === 0` → 拒绝。

**关键**：`v` 完全不参与版本分派。`{"_t":"lc","v":3,"en":"future"}` 会被 V2 读取器当成 V2 卡片渲染（测试向量已验证）。

## 4. 读取端的宽容行为（V2 事实）

| 行为 | 说明 |
| --- | --- |
| 前后夹带文字 | 允许；只取第一个 `{` 到最后一个 `}` 之间 |
| JSON 解析失败 | 用正则白名单 `"(_t\|en\|ja\|jp\|zh\|cn\|v)"\s*:\s*"([\s\S]*?)"` 抽取字段，只认**双引号字符串值**，并反转义 `\n`、`\"`。数字 `v:2` 在兜底里会丢失，但 `_t:"lc"` 卡片仍可识别 |
| 语言值非字符串 | `String(val).trim()`，不报错 |
| 未知键 | 静默忽略 |
| 遗留键 | `jp` → `ja`、`cn` → `zh`；`data[key] || legacy || ''` |
| 空值 | `""` / 全空白视为该语言不存在 |
| tags | 只从 JSON **之后**的文本提取；`#` 开启新 token，逗号**不是**分隔符（`#a,#b` 会切成 `#a,` 与 `#b`） |
| 全角 `＃` | 读取端不认（怪癖，见 §8.7） |

**渲染规则**：卡片只展开「实际有内容」的语言 section（`cardPresentLangs`）；一个都没有时（例如只有 `_t/v` + tail tag），回退到全局语言开关的组合。已渲染的容器用 `data-lc-raw` 缓存原文，避免 Memos 重渲染时把自己的 UI 当成数据源。

## 5. 写入规则

`buildCardPayload()`（`src/editor.js`）：

```
data = { _t: "lc", v: 2 }
for lang of CONFIG.languages:
    val = input(lang.key).value.trim()
    if val: data[lang.key] = val          // 键序 = JA → EN → ZH
tags = tagsInput.split(/[\s,]+/).map(补 "#").filter(len>1).join(" ")
content = JSON.stringify(data) + (tags ? "\n" + tags : "")
```

- 至少一个语言槽非空才允许保存（只填 tags 会被 `Please fill in at least one language slot!` 拦下）。
- 创建：`POST /api/memos`，body `{ content, visibility: "PRIVATE", space? }`。
- 编辑：`PATCH /api/memos/{bareId}?updateMask=content`，body 同上，但**只更新 content**；`bareId` 来自 `data-lc-memo-name`（`memos/xxx` 去掉前缀）。
- 新 API 路径遇 `404/410` 自动回退 `/api/v1/...`（Memos 0.31 与 26.10+ 双代兼容，详见根 README）。
- Space 归属优先级：**专属 Space**（§6） > URL `/s/<id>`（转成 `spaces/<id>`） > 不传 `space`（个人空间）。
- `401` 会刷新 token 重试并清 Space 缓存；`403` 清 Space 缓存。
- 保存成功后**不刷新页面**；编辑模式用 `refreshCardLocally()` 原地重绘。

> **编辑会丢弃未知字段**：打开编辑器只预填 `CONFIG.languages` 的三个键，保存时从零重建 `data`。
> 旧键 `jp`/`cn` 会被规范化成 `ja`/`zh`（值不丢），但任何额外键（如 `fr`、`note`）以及 JSON 里的其它元数据都会消失。
> V3 若要新增字段，必须同步改编辑器的预填/序列化逻辑。

## 6. Space 标记（与卡片共用 `_t` 命名空间）

把仅含 header 的 JSON 放进**某个 Space 的 `description`**：

```json
{"_t":"lc","v":2}
```

| 规则 | 实现 |
| --- | --- |
| 提取 | 第一个 `{` 到最后一个 `}`；`JSON.parse` 严格，**没有正则兜底** |
| 判定 | **只检查 `_t === "lc"`，不检查 `v`**（`{"_t":"lc","v":3}` 也命中） |
| 数量 | 只允许一个；多个 → 指示器警告且不选目标；零个 → 引导用户设置 |
| 缓存 | `localStorage["memos_lc_target_space_v2"]` = `{ name: "spaces/xxx", title: "..." }`；兼容旧的裸字符串值 |
| 存取 | `GET /api/spaces`（回退 `/api/v1/spaces`），分页 `pageSize=1000` |

`CONFIG.dedicatedSpaceKeyword` 是另一套**已禁用**（值为 `null`）的机制：非 null 时既限制悬浮栏只在匹配 URL 出现，也让该 Space 内无 `_t` 的 JSON 被识别成卡片。

## 7. 客户端状态（不是卡片数据，但属于 V2 运行环境）

| localStorage 键 | 值 |
| --- | --- |
| `memos_lc_enabled_langs_v2` | JSON 数组，全局语言开关；默认 `["en","zh"]`，至少保留一个 |
| `memos_lc_target_space_v2` | `{name,title}` 或遗留裸字符串 |
| `memos_access_token` / `memos_token_expires_at` | Memos 自身所有；插件只读，过期时静默刷新 |

DOM 运行时标记（非持久化）：`data-lc-raw`、`data-lc-parsed`、`data-lc-force`、`data-lc-memo-name`、`data-lc-quick-actions`、`<style id="lc-injected-style">`。

`CONFIG.languages[]` 每项还带 `label/code/color`（UI 已使用）与 `ttsLang/placeholder`（**当前没有任何读者，是预留扩展位**；编辑器里的 placeholder 文本是硬编码的）。

## 8. 已知限制 / 怪癖：V3 决策清单

> 实现状态：以下条目已按 `schema/v3.md` §1 落地，仍作为持续复核的兼容约束保留。

1. **版本字段不用于分派**：V2 读取器看 `_t`、不看 `v`。V3 若在 `v:3` 的同时保留 `_t:"lc"`，旧插件会把它当 V2 渲染。需要先定策略：换新 `_t`、在读取端按 `v` 分派、或双写兼容字段。
2. **README 里「新增语言只需改 `CONFIG.languages`」并不完全成立**：`hasLang` / `hasValues` 与正则兜底白名单都硬编码 `["en","ja","jp","zh","cn"]`。只含新语言（如 `fr`）的卡片会被判为「无内容」而拒绝渲染。V3 加语言必须同步改这三处（还要看 §5 的键序）。
3. **Space header 不检查 `v`**：升级卡片版本不会让标记失效；但 V3 若允许多个带 header 的 Space，就得重新定义「唯一目标」规则与指示器语义。
4. **tags 在 JSON 之外**：V3 若把 tags 移进对象，V2 读取器不会显示 chip；反之 tail tags 可以继续被新读取器兼容。
5. **`_t` 非 `lc` 直接拒绝**：换新标识符会让 V2 完全看不见新卡片，这可以当作「只让新版本可见」的开关。
6. **读取端比写入端宽松**：只有 tail tag、没有语言值的卡片合法（渲染 0 列并回退全局开关），但编辑器不允许只填 tag 保存。V3 要决定是收紧读取还是放宽写入。
7. **全角 `＃`**：读取端只认半角 `#`；写入端 `t.startsWith("#")` 会把 `＃tag` 变成 `#＃tag`。
8. **正则兜底只认 7 个键且只认字符串值**：V3 新增字段在 JSON 损坏时会丢失，若新字段是必需信息则不能依赖宽容解析。
9. **编辑 PATCH 只更新 `content`**：新增元数据放 `content` 内没问题；若放 memo 的其它字段，需要改 `updateMask` 与创建/编辑两条路径。
10. **localStorage 键带 `_v2` 后缀**：V3 需决定复用还是新增键并迁移旧值。
11. **没有批量迁移能力**：插件只用网页 session，没有 PAT/后台脚本，历史 memo 无法在升级时批量改写。因此 V3 必须让**读取器**同时认识 V2（和更早的无 `_t` 卡片），不能假设数据已被转换。
12. **编辑会重建整个对象**（§5）：给 V3 加字段时，旧卡片一旦被用户编辑就会丢失未接线的新字段。

## 9. 一致性测试向量

`tools/schema-v2.test.mjs` 直接调用 `parseCardMemo` / `cardPresentLangs` / `parseSpaceHeader`，覆盖 21 个断言：

| 输入（要点） | V2 结果 |
| --- | --- |
| `_t:"lc", v:2, ja/en/zh 齐全 + \n#vocab #daily` | 有效，3 列，2 个 tag |
| `_t:"lc", v:2, en` 单项 | 有效，1 列 |
| `_t:"lc", v:2, fr`（新语言） | **无效**（白名单限制） |
| `_t:"lc", v:2, en:""` | 无效（无内容、无 tag） |
| `_t:"other"` | 无效（防误判） |
| `v:2, en`，无 `_t` | 有效（V1 遗留卡） |
| 无 `_t` 无 `v` | 无效 |
| `v:"2"` + `jp`/`cn` | 有效，映射成 `ja`/`zh` 两列 |
| `v:3` + `_t:"lc"` | **有效，仍按 V2 渲染** |
| 只有 `_t/v` + tail tag | 有效，0 列（回退全局开关） |
| JSON 前后夹文字 | 有效，tail tag 仍可提取 |
| 尾随逗号（坏 JSON） | 有效（正则兜底，`v` 丢失但 `_t` 保留） |
| `en:123` | 有效，渲染 `123` |
| `#a,#b` | 切成 `#a,` 与 `#b` |
| 数组 payload | 无效 |
| Space header `v:2` / `v:3` / 夹文字 | 都命中（只验 `_t`） |
| Space header `_t:"other"` / 坏 JSON | 不命中 |

V3 改动读取器后，这张表就是必须逐条复核的兼容清单。
